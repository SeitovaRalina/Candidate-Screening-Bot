# User Stories

## Recruiter

- As a recruiter, I send the bot a vacancy link (hh.ru) and a candidate's resume file, so I get a screening card without doing the comparison by hand.
- As a recruiter, I want the verdict explained with quotes from the resume, so I can trust it without re-reading the whole resume myself.
- As a recruiter, I want red flags (inflated experience, date overlaps, irrelevant content) surfaced explicitly, so I don't rely on catching them manually every time.
- As a recruiter, I make the final invite/reject call myself — the bot's verdict is input, not the decision.

## Technical interviewer

- As a technical interviewer, I want a short list of questions targeted at the candidate's specific gaps or red flags, so I can probe them directly in the interview instead of asking generic questions.

## Anton (client, decision maker)

- As the client, I want to approve or correct the screening-criteria list before the engineer builds against it, so the prototype matches what I actually asked for and not an assumption.
- As the client, I want to see a working prototype 2.5-3h after the kickoff meeting, on at least one real vacancy+resume pair.
